## 2. 来源与状态语义

- `scope`、`conversation_id`、`request_id`、消息 ID、角色、说话者和接收时间必须来自应用可信输入，不由训练标签或模型虚构。
- 同一记忆作用域允许跨聊天读取；不同作用域拒绝混用。字段相等校验不是身份认证，HTTP 授权与绑定在 P5 验证。
- 消息按应用序号排列，以本次用户消息结束；拒绝时间晚于当前时点的消息/事件。消息正文是否偷塞了参考答案仍需数据审计，类型检查不能代替它。
- 来源位置使用 UTF-8 字节偏移并校验字符边界；精确 tokenizer token 对齐、特征维度和序列切分留待 P1.7 及接口补齐，不能由字节偏移推断 token 位置。
- `learned_at_ms` 是获知时间；`event_time` 是模型解释的事实时间，可未知，不自动按写入顺序判新旧。
- `fact_status` 默认 unknown；actual/negated/hypothetical/quoted 是模型输出状态。存储校验不根据关键词把它改为 actual，也不把这些字段的存在等同于模型已经学会判断。
- 写入支持空增量、多单元、追加、替代、并存和撤回；读写独立。只验证候选来源、版本、目标与操作，不执行持久化或声称重放幂等已实现。
- 读绑定固定 revision 和模型身份，拒绝撤回事件。复制地址必须落在被激活事件来源之内；NULL/disabled 没有 payload，多个独立激活不强制归一化为 top-K。

## 3. 评分口径

每个被评审的事实必须包括主体、关系/角色方向、值、时间及事实状态；正确值子串不构成通过条件。
评分比较独立评审得到的完整事实集合：必要事实必须齐全，额外断言必须有允许的证据。
无证据题还要求表达不确定；自然性和不必要的记忆旁白独立计分。
合理代词由评审结合当前语境消解，不要求回复机械重复人名。

评审记录绑定回复 SHA-256 与评审者标识。协议返回三种状态：

- `pass`：独立评审记录满足该题全部要求。
- `fail`：违反任一要求；空回复直接失败。
- `needs_review`：非空自由回复缺少独立评审，不做自动正确性猜测。

此处的评审者标识只是可追溯字段，不是可信评审的自动证明。正式数据还需独立人工校准与复核流程，
不能让被测模型填写自己的评审记录。当前测试中的评审是人工编写的对/错样例，不是实际模型输出。
统计时必须保留待评审数量与总数，禁止从分母移除待评审样本后宣称高准确率；最终验收需完成所有必要评审。

已覆盖的评分反例：值对人错、关系错、旧时间冒充当前、否定/假设冒充事实、角色倒置、
遗漏多事实、混入无依据的他人信息、空回复、无依据确定回答、不自然回复和操作旁白。
已有这些评分反例，不等于 P1.4 的完整多语言语义世界/自动写入场景集完成。

## 4. 测量与启动拦截

`InferenceTrace` 要求显式提供缓存开关/计数、标签与未来消息字段、oracle 条件、人工写入边界、
持久来源 prompt 注入、整句输出替换、是否实际经过 decoder；缺失字段不得默认成“安全”。
这里的来源注入指把持久记忆原文追加到生成 prompt，不禁止正常的当前/近期用户对话。
oracle 激活只允许作为明确标记的 oracle 组件实验；人工写入边界不能被叫作端到端自动记忆。

这些检查能拒绝不合规记录，不能识别虚假的安全声明。已用实际 `EpisodeBindingReader` 前向 hook 检查：
调用只收到 query/episode 张量；固定权重时，修改监督不改变编码文本、特征或 logits，但可以改变 loss 和评测期望值。
旧数据适配器也用本机 C tokenizer 做了标签变更对照。边界测试使用合成特征，不是 backbone 能力测试。
P1.6 仍需完整链路未来内容/答案前缀及运行时缓存计数接线验证，不能声称整个系统已经无泄漏。

训练入口当前无放行分支：P1 未完成会拒绝；即使仅修改 JSON 中 `prerequisites_complete=true`，
未审查草稿仍会拒绝。以后必须在完成 P1、审查草稿并补齐源码/数据哈希、种子和命令验证后，

## 5. 固定小型数据与统计单位

`data/P1-smoke.json` 固定 16 个语义世界和种子；每个世界生成 22 种场景 × 中英文两种表达。
训练/开发各 8 个世界、352 条，共 704 条。中英文、改写、换值、删除和干扰变体均整世界分组；
352 条开发样例只有 8 个独立世界，不能按 352 个独立样本计算置信区间，更不能据此通过正式阶段门槛。
当前两侧主体不重叠，值、关系和模板共享；不宣称未见关系/问法泛化，也不是独立最终测试集。

场景包括原始/改写/换值、同值不同人、错主体、错关系、目标移除、无关事件、
干扰增加/重排、多目标、角色方向互换、假设、否定、未确认转述、更新/历史、指代、别名、空库及普通聊天。
读写混合、长输入、真实同名歧义、复杂多跳、撤回与自动 writer 来源归属仍需补齐，P1.4 未整体完成。

监督分开存储 `relevant_episode_indices` 和 `required_claims`：假设/否定/未确认转述可以是相关证据，
但不能证明正向确定事实。reader 不能把“相关”直接等同于“可当真实答案使用”。
这些是离线标签，不进入推理特征。新数据尚未接入草稿的旧两关系监督训练格式。

六个数据文件分别是 train/dev 的 inputs、labels、index；索引保存世界血缘和规范事实。
校验世界 ID、规范世界内容、事件集合及单事件事实是否跨集合重复，忽略表述和事件排列；
改一个 world ID 或把重复事件包进新集合不能绕过检查。空库不因共同为空被误判为泄漏。
此方法依赖合成器的规范语义，不是对任意自然文本的语义去重器；完整重生成及文件哈希用来防止侧文件被篡改。

`data/P1-smoke.manifest.json` 保存生成器/输入适配器/配置/六个产物的 SHA-256。
测试要求重新生成结果与此登记清单一致；改数据或生成规则必须显式审查并更新清单，不允许悄悄漂移。
`--verify` 同时拒绝缺失、修改和混入的额外文件。

输入适配器以固定 JSON 消息框保留 role/speaker/text，并将每个来源单独编码，绝不追加到 query。
该诊断消息框不同于旧草稿的裸文本特征域；不得直接复用其缓存/权重。最终编码协议及 C 对齐仍由 P1.7 冻结。
