# CG-003：两组训练后的完整C生成与双评审

结论：**两个候选均未通过预登记门槛，不选优、不部署、不追加训练。**
本实验是同一0.5B骨干上的单个给定复合事件、一个固定开发世界的组件验证，
不是自动写入、完整C/HTTP系统、封存测试集或LoCoMo成绩。

## 1. 固定方案与产物

两组均按批准预算训练50步，相同初始参数、数据和200对采样表。没有增加种子、恢复旧检查点或额外步数。
骨干SHA `44cb4e0db8374d4247bba391b3d3b7c0b3ee815c36cf2e20d0d1a3570677bd95`。
候选SHA：

- aux：`fb4728d552c63d4ca6881b7141766240a1df3abf3c73e7b92a40d69475d3dc36`。
- product：`d40a254c82aa1602b5e1c2bfa63dc971f7079666539bf1fb9550e3a43f7cff8a`。

沿用预先冻结的24例、greedy、64-token上限、128-token容量；没有因观察到重复或错误而删题、缩短样例或调整阈值。
两组各24条加原基线24条，共72次用例结果。test保持封存，没有用于生成或选择。

## 2. C链路与独立轨迹核验

神经模块与概率混合仍在Python；同一冻结骨干、源文本编码及连续输出投影由C执行。
每个位置重新计算自然问题加实际已生成token的完整前缀，不把来源原文或参考答案放入生成提示。
没有跨请求/位置KV复用；单次prefill内部仍使用K/V工作缓冲。来源由测试提供，不是已训练的自动writer。

`audit_joint_generation.py` 重新读取全部原始文件，独立检查：

- 输入来源字节和C tokenizer token；自然初始前缀、随后每个实际预测token。
- 每个C文件SHA、格式、长度、前缀、注入残差，以及fresh-context轨迹。
- C普通reference与base的hidden/logits逐位一致；训练模型重新预测的初始路线及固定状态概率一致。
- 连续投影和copy混合与训练模型一致；`atol=1e-5, rtol=1e-4`且top-1相同。
- normal路线完整回复与基线token/字节相同；停止符、截断和UTF-8标记对应原始字节。

两组普通算术均保持原始基线；总通过13/24主要来自算术与部分拒答，**不是54.2%的记忆准确率**。
在这个固定小面板里有依据回答都是1/8（12.5%），不能推广成全量记忆准确率或与不同旧面板直接比较。
唯一通过的记忆问题均为中文home-city换值后的 `Riga`；另一端没有正确输出 `Queretaro`，所以成对验收仍失败。
评分与选择记录见 `score.json`：两个 `pilot_gates_passed=false`，`selected_arm=null`，部署和追加训练均不批准。

典型失败：

- aux对英文正确来源也回答“不知道”，把有证据的recall一并拒绝。
- aux的部分中文insufficient路线仍回答东京，说明“路线判对”不保证拒答文本正确。
- 两组输出 `Quererer` 或 `Querer`，没有完整保留城市名称。
- product角色交换反例仍选supported；部分回复连续重复 `currently` 直到64-token上限。

## 5. 可以得出的结论与不能得出的结论

已核对的882个生成位置没有显示C接入与Python训练模型的数值分歧。
当前失败不能简单归咎于移植计算或历史KV冒充记忆，也不能用这些工程检查通过来宣称语义能力成功。
本实验没有使用SVD、NAS或LoRA，不能把这些结果解释为压缩损失。

重复问题也不能只怪copy通路：7条截断轨迹共448个位置，按实际前缀重算时，
去掉copy项后的连续内容分支top-1与实际输出 **448/448相同**。
其中连续内容分支相对未加记忆的base改变了34个位置的top-1（aux4个、product30个）。
这表明连续内容增量可以把输出带入重复轨迹；copy不是这些已观测循环的必要驱动。
这是在同一实际前缀上的只读分解，不是另跑了一套完整自由回复，更不是“关闭copy能提高准确率”。

联合绑定、精确多token值输出和缺证据生成都仍有失败。现有证据不证明0.5B骨干原则上不能记忆，
也不证明整个神经记忆方向不可行；它否定的是这两个候选已经达到当前门槛。

下一项应先登记无参数更新的内容分支消融：区分连续内容增量、神经位置激活和copy对真实自由回复的作用，
并分别检查绑定判断与完整值读出；不能只看teacher-forced loss或状态分类。
不直接增加训练步数、不把乘法组的170/192分类分数当作选优依据。新的训练方案须另行登记和批准。

本轮Python **261/261**、CTest **21/21** 通过。未修改训练权重，未提交代码，未替换部署模型。
