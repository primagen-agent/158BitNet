# DG-016：冻结实际token前缀的值续接

这是V1人工句柄的软件/C兼容性检查，不是神经激活或记忆准确率测试。
没有训练新模型，没有改旧checkpoint，不部署到服务。预登记见 `../../experiments/DG-016.json`。

结果：**14/14条符合新契约预期：12条完整传递、2条安全拒绝；44个实际C前缀、88次C调用全部通过。**
本次限定范围的V1字节传递/边界软件门槛通过，不表示P2神经记忆能力或完整系统门槛通过。

## 新旧契约分开

DG-015的实现、11条预期和10/11结果保持不变。
DG-016新增 `append_value_transport.py`，显式取消“拼接结果必须等于整段文字重新编码”的要求，
改为“实际token前缀逐个保持不变，新增token解码字节精确等于所选值”。
这不是新的Python tokenizer，也不是偷偷把旧失败改判通过。

原11条自然输入不变。新契约对空格/字母合并边界要求成功续接；控制token和超预算仍要求拒绝。
额外固定3条：非canonical实际前缀、多行值、多个前导/尾随空格，共14条。
所有事实/值选择都为显式人工oracle，不由模型预测。

## 如何得到后缀

使用同一C tokenizer分别编码固定边界标记和“标记+值”，验证标记的token前缀完全相同，
只保留之后的token，并检查其解码字节完整等于值。标记为`<|im_end|>`，仅用于分词隔离。
它连同BOS/可选dummy空格只从临时分词结果中按已验证的完整前缀移除；不截取普通token的半个字节，也不strip值。
来源值里的控制token仍被拒绝。边界标记不进入C backbone，不进入输出，不改变现有回复token。

续接允许采用不等于整串canonical BPE的合法token序列。两种分词即使文本相同，也可能产生不同隐藏态和logits；
本试验**不要求或声称跨分词数值相等**。只核对相同实际token输入下的两条C执行路径。
值的语义选择依然不属于传递算子；这个算子不能证明所选事实/跨度正确。

## 实际C检查

`check_append_value_transport.py`对每条成功编译的值：

1. 每个值token发出前，在确切实际前缀上执行普通C reference和零增量continuous probe。
2. 重读原始输入/输出文件，核对token ID、fresh-context trace、FP32隐藏态/logits逐位相同、增量为零。
3. 游标选择下一个值token，提交后验证旧前缀未改、已输出字节保持一致。
4. 值结束后再做一次相同C检查，确认游标把基础argmax原样交回；不继续生成整段回复。

每次都是新进程/新context/完整prefill，没有跨步骤KV复用；单次prefill内部仍有K/V工作缓冲。
原始文件保留在`build/neural-memory-dg016-native/`，完整分母和逐位置结果保存在`native-fixtures.json`。
127项原训练源文件/证书/checkpoint，以及DG-015模块和两份C探针执行前后检查身份，不修改冻结实现。

最终报告SHA-256：`a5146681a1ac937bb57ca1f0a7bd372895b7f58125d0971e3d6d0cd6eaba2658`。
运行后再次独立重读全部报告/原始文件：14条清单、每一步实际prefix/token、隐藏态/logits、零增量和最终base选择均匹配。
每条已接纳值的最后一个位置只检查交回base，未继续生成自然回复；44个位置中32个是值token位置、12个是交回base的位置。

## 能证明与不能证明的范围

通过只能说明：在给定正确值句柄的这些人工边界用例上，字节传递和C实际前缀消费兼容。
不能说明：自动选对事实、自动判断开始引用、完整自然回复正确、自动写入、忘记/更新或HTTP已经完成。
交回base后，模型仍可能继续扩写名称或添加不实信息；必须在后续完整回复评测中保留此风险，不能以值字节正确替代。

新的神经/训练接口必须按这个实际token轨迹制作监督和C特征；不能直接复用整串canonical前缀特征来宣称数值对齐。
NULL、非值copy关闭、开始/结束、同事实联合判断都仍需单独学习和检验。
CG-003预算已经用尽，本检查没有新增训练授权。

下一项是V2神经联合事实/跨度/值模式接口与监督的零更新验证：运行输入与标签分离，保留NULL和普通旁路，
按新的实际token轨迹核对C特征与训练目标。尚未实现的神经选择不能以人工oracle句柄顶替；没有批准新训练。
