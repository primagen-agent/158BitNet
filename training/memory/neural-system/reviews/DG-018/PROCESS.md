## 1. 新接口解决什么

`fine_span_reader.py`保留token粗跨度选择，再对事实和值分别预测起止字节位置。
四个边界头的所有位置分数一次前向计算，使用冻结C特征、查询/来源投影和可学习的token内偏移嵌入。
不按城市名、空格、标点或主体关系规则定位边界，不调用strip，不把正确范围传入网络。

运行输入的原始字节只用于校验来源身份、构造全部合法UTF-8字符切点和token偏移映射；
边界的神经评分不接收目标文字/边界。比如` A`的合法起点同时包含空格和A，不能提前把空格排掉。
如果一个UTF-8字符跨两个C token，仍按完整来源字节确定合法切点，不能切在字符内部。
没有合法起点或终点的单token跨度被结构性排除，但可与相邻token合并为包含完整字符的粗跨度。

粗跨度限制保持每段最多16 token、payload最多32 token、总特征最多512行；每个payload token最多64字节。
超容量/损坏UTF-8显式拒绝，不能截断记忆。宽64是未训练接口配置，不是已经选定的高精度架构。
本原型尚不是长上下文/大容量记忆的可扩展实现。

## 2. 四个边界必须共同合法

强制满足：`事实起点 ≤ 值起点 < 值终点 ≤ 事实终点`。
使用四阶段动态规划计算合法路径的log-sum-exp归一化与最大分数路径；
每阶段最多65×65转移，不创建四个边界的完整笛卡尔积张量。

在log-sum-exp之前同时去掉从起点不可达、到终点不可达的状态，防止全负无穷行反向产生NaN。
小型穷举夹具核对归一化、最大路径和梯度；不可达位置的梯度为零且有限。

推理先选粗事实/值组合，再选其条件下的细边界。**这是分层解码，不是整个粗细联合分布的全局MAP**，
可能存在粗选择最优而细组合并非全局最优的情况，需要后续实验评估。
结构嵌套仍不证明事实语义正确；较大范围也可能错误涵盖两条事实。

## 3. 监督没有进入预测

`fine_span_supervision.py`只在完整神经前向后读取精确字节标签。
先从现成的粗候选分布取标签项，再用现成的四组边界分数计算条件NLL；
标签只决定loss索引和条件分区，不触发一次gold条件下的新神经前向。
事实、值、字节边界、路线及idle模式共同组成损失。负例没有正值边界监督。

预测句柄只使用模型自己选出的字节范围；绑定模型参数摘要、来源字节、上下文和编码域。
人工强制START的分支测试仍是软件夹具，不混入真实随机预测记录。
模式仍只覆盖idle GENERATE/START接口；引用中的顺序/结束由已选值边界和游标确定。
完整回复以及交回base后的语义边界尚未验证。
