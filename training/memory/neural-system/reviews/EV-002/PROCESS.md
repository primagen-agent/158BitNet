# EV-002：V3-002（损失加权修正候选）评估

结论：**未通过，且与EV-001逐字节相同。** 损失加权（route 4.0、start-mode 4.0）未能改变结局——
参数摘要与损失曲线确实不同，但路由/mode结果在892条训练项上**逐位复现**V3-001的退化吸引子，
24条自由回复与EV-001完全一致。按注册判定规则：**冲突是结构性的**。

## 事实链

1. 训练真实不同：reader摘要 2ba652e6… ≠ a718b4c6…；加权损失曲线更高（step25 1.98 vs 1.42）。
2. DG-027式探针（ckpt-050，892项）：混淆 [[48,48,0],[0,268,0],[96,432,0]]（与V3-001相同），
   supported 100%正确、insufficient 432/528误路由p1、mode start 0/268。
3. EV-002自由回复评估：24条回复、停止、packet id与EV-001**全部相同**（C链路重新实测认证）。
4. 按EV-002注册的复用规则：同packet id复用EV-001双盲评审（CG去重惯例，已披露）；
   门槛判定相同：normal 4/4✅；uncertainty 3/10❌；grounded 0/10❌；截断10/24❌。

## 解读

同一初始化+同一数据顺序下，4倍route加权仍无法让route读出层摆脱被共享干路表征主导的退化解：
span/fact/value头所需的表征把r1/r2聚在一起（都有来源与跨度），线性route读出无法在其上分开
"是否存在当前事实"。mode头同理（start从未成为argmax）。这是表征/读出结构问题，不是权重问题。
