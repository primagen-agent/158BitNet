# DG-008：主体绑定与内容信号在哪里失配

结论：本轮没有发现输入漏掉姓名/城市，发现的是 **主体判断未正确区分来源，且值相关变化相对于共同输出偏置太弱**。
不是完全没有学习，但也远未形成可用 recall；不能把本轮诊断数字当作新的记忆准确率。

登记 `experiments/DG-008.json`；实现 `python/diagnose_role_content_path.py`；
完整证据 `checks/DG-008-result.json`。不更新参数、不扫描增益、不训练探针、不启动第三个候选。

## 1. 控制变量先修正

原数据的 `wrong_subject` 同时换了主体和值，不能直接与 `original` 比较后把差异归因于主体。
本轮使用全部 8 个开发世界、两种语言，共 48 条来源记录，建立两种独立对照：

| 条件例子（问题都询问 Adela） | 主体 | 城市 |
| --- | --- | --- |
| original | Adela | Rennes |
| swapped_values | Adela | Turin |
| wrong_subject | Boris | Turin |

- 值对照：original ↔ swapped_values，16 对，主体不变。
- 主体对照：swapped_values ↔ wrong_subject，16 对，城市不变。

代码验证相同问题、角色、事件数量及其它事实字段，来源原文只允许指定字段替换。
这是额外诊断，未修改此前固定 16 条自由生成的分母或 0/8 recall 结论。

## 2. 输入没有漏编码，但不等于已能正确读取

48/48 条来源的 C token ID 和还原字节核对通过，原始主体/城市的 token 位置均保留。
32 个待测的首个差异值 token，32/32 能在对应来源值的 token 区间中找到。
这个区间来自后置诊断标注，**没有拿来屏蔽注意力、选择记忆或生成答案**。

因此可排除“这批来源根本没编码进来”的简单解释；不能据此推断自动 writer、持久化或神经读出已经成功。
当前神经模块使用浮点特征，原始 token ID 的可用性只是后续精确输出通道的条件，不是一个已训练的 pointer。
这批城市词在训练城市集合中出现过，开发集按世界/主体分开；不是任意新值的泛化证明。

## 3. 主要观察

### 主体判断没有完成绑定

初始用户 prefill 上，16 条正确原值、16 条正确换值和 **16 条错主体来源全部被判为证据可用**。
单独换主体时，支持概率差的中位数仅约 `0.00054`；只有 11/16 对的差异方向偏向正确主体。
来源表示本身存在变化，但分类器未把变化转换为有效的主体归属判断。

这不证明查询 hidden 永久缺少主体信息，也不证明某一个参数矩阵是唯一根因。
本轮只在初始用户前缀观察状态，不在参考答案前缀重新判定路线。

### 值信号存在，但相对差异在输出映射后很小

在两个正确参考回复的首个差异值 token 之前，使用完全相同的因果前缀，分别送入两份不同来源。
该位置不含当前/未来目标 token；前面的回复 token 是教师强制，因此主要是 oracle 组件诊断。

| 同一位置的换值变化（16 对的中位数） | 相对 L2 差异 |
| --- | ---: |
| 神经读取向量 | 4.13% |
| 经过输出矩阵及相同 gate/gain 的内容增量 | 0.280% |

这里比较的是各阶段的“差分相对共同信号”的比例，不是信息论丢失率；不能简单宣称信息不可恢复。
但它表明：当前投影更偏向共同成分，来源差异尚不足以控制输出。

值 token 的平均注意力密度约为均匀分配的 0.697 倍，32 个观察位置均低于均匀值。
这是描述性证据，**不是因果解释**：其它位置的上下文特征也可能携带城市信息，不能只看注意力位置下结论。

### 不是完全没有学习，也不是已经记住

换值导致的两候选相对 logit 变化方向 **16/16** 偏向对应来源值，但幅度中位数只有约 `0.0060`。
用 FP64 的线性对比独立检查了这个小差分，与 FP32 完整 logit 的差分在登记容差内一致。
这比“模型对来源完全不敏感”更准确，但效果仍不足：

- 两候选互换后两端都选对：**0/16**。
- 全词表中首个目标值 token 成为 top-1：**0/32**。
- 目标 token 排名中位数：基础模型 `2206.5`，条件化后 `895.5`，仍远离第一名。
- 这些 32 个参考前缀中，只有 **2 个**与已记录自由生成的 token 前缀完全一致。
  因此不能把上述方向或排名统计包装成真实生成准确率。

若 `m_A = z_A(a)-z_A(b)`、`m_B = z_B(a)-z_B(b)`，则两端都选对要求
`m_A > 0` 且 `m_B < 0`。令条件效应 `d=m_A-m_B`、共同中心 `c=(m_A+m_B)/2`，等价于 `d > 2|c|`。
当前 `d/(2|c|)` 的中位数仅约 `0.001094`。它只是说明条件信号相对偏置很弱，
**不意味着把整个记忆增量乘约 914 就能修复**；那也会改变共同偏置和普通聊天行为。

## 4. 训练覆盖也是限制，不能只怪结构

另对已经完成的训练日志做了单列的探索性审计，没有改变本轮探针分母：

- 50 步 × 4 条，共 200 次采样；有证据样例 63 次，错主体样例 14 次。
- 按既定状态样本权重，有证据名义曝光量为 126，错主体为 14。
  这是样本/权重统计，不是实际梯度贡献比。
- 32 对“城市相同、主体不同”的训练对，只有 8 对两端都至少出现过一次；原训练也没有成对目标。

因此当前证据不能区分为单纯的结构容量问题，或单纯的数据量问题。
整句 CE 可以通过常见措辞/城市先验降低，而不必让来源变化足以改变答案；
较少的主体对照又不足以证明已经学会归属匹配。**盲目增加步数或统一放大增量都不是本轮结论。**

## 5. 新的推进方案

保留已验证的同一 0.5B、静默神经控制、固定首轮读决策和普通聊天保真边界。
优先级从“继续优化整句回复”调整为“让来源变化能够控制主体归属和具体值”。

1. **成对主体监督。** 同问题、同关系、同城市，仅换主体，联合比较正确来源与错人来源。
   除原状态 CE 外，检查成对目标是否真正增强来源条件差异，而不是只降低所有样例的同一个偏置。
2. **成对值监督。** 同问题、同主体，交换值，单列值 token 的完整词表 CE 和两源条件差异。
   两候选对比本身不够：必须同时防止词表中其它错误值仍占第一，最终仍验完整自由回复。
3. **保留 token 级神经读出选择。** 若差异仍在聚合/输出中变弱，再验证 DESIGN 已允许的 token/payload 通道：
   只能由神经激活选择来源和位置，再参与逐 token 输出；不得按标签/正则查答案、拼接来源原文或返回整个固定答案。
   源/目标 token 边界不同、字节 token、重复值、错主体和缺失目标都必须单独验收。

**零 optimizer step 的成对目标/梯度方向验证已完成**，见 `PAIRED_OBJECTIVE_DIAGNOSIS.md`。
它增强了来源差异方向，但还不能证明足以修复 recall；下一项为主体匹配与 token 值读出分离接口审查。
不在开发集上搜索 loss 权重、增益或 checkpoint。现有两候选预算已用完，新训练须重新登记范围和预算，不能改名绕过。
本轮没有实现或训练新的部署模型，也没有宣称 pointer 已可用。
