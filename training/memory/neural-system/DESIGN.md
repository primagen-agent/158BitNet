# 自然对话神经记忆系统：设计基线

状态：设计与执行约束，不是已完成能力声明。配套执行顺序见 `PLAN.md`。

## 1. 产品目标与不可变约束

用户只需正常交流。系统自动判断需要保留的信息，以及当前回复是否需要利用记忆。
同一轮可以同时写入和唤醒。默认不播报“我记住了”，也不解释“我查询了记忆”；
记忆应自然影响回复的内容和约束。用户主动询问记忆或要求遗忘时，可以正常回应。

固定约束：

- 只使用 SHA-256 为 `44cb4e0db8374d4247bba391b3d3b7c0b3ee815c36cf2e20d0d1a3570677bd95` 的 0.5B GGUF。
- backbone 参数冻结；训练写入、地址/关系、激活、融合及必要的复制模块。
- 不使用 LoRA、SVD、NAS/NG 压缩；首先验证准确性。
- 不复用 backbone KV cache；诊断阶段 decode 每步重新计算当前前缀。
- recall 通过模型内部的神经激活完成，不生成检索语句，不调用文本/向量检索服务，不向提示词拼接历史原文。
- 数学上的 attention query/key/value 不是聊天 KV cache；持久记忆由独立的记忆写入过程形成。
- LoCoMo 仅作最终独立评估，不进入训练、阈值标定或检查点选择。
- 推理时模型参数不更新；变化的是用户的记忆状态，不能把训练特定用户事实当作记忆能力。
- 未通过对应阶段验收，不替换现有部署模型，不把组件实验称为自动记忆成功。

## 2. 设计决策

### 2.1 保留情景边界，并分开地址与内容

主要记忆单位是有来源的情景/事件，可以包含多个相互关联的事实。
每条输入可以产生零个、一个或多个记忆单元。

每个单元同时保存：

1. 来源字节、精确 token/payload 位置、说话者、作用域和事件 ID。
2. 由模型学习的地址和内容表示；第一阶段保留细粒度 token 信息。
3. 时间、可信程度、实际/假设/引用/否定等状态；无法确认时保持未知。
4. 与其他事件的追加、替代、补充、并存、撤回关系。

结构化字段是辅助监督和可追溯信息，不是所有记忆都必须通过的固定三元组入口。
主体可以是人、项目、组织或一个事件，不能把单个人名向量当成所有地址。
必须区分角色方向，例如“A 把书借给 B”和“B 把书借给 A”。

### 2.2 神经激活按事件组织

先根据当前对话形成神经线索，再判断各个记忆事件是否相关和有效；
在被激活事件内部读取内容。不同事件的 token 不能失去所属事件的信息后任意混合。

激活至少联合考虑主体/角色、内容关系、时间范围、事实状态和来源。
允许零条或多条相关记忆，不由独立的数量头强制取 K 条。
初版使用精确、可核验的神经读操作，暂不引入 ANN 索引或检索式候选筛选。
阈值只能在预先定义的开发协议中确定并冻结，不能在测试时按样本调整。

更新关系采用有方向、可解释的关联；不能将所有后续事件的微小覆盖概率无限连乘。
事实的发生时间与获知时间分别保存，不能把“晚写入”一律解释为“事实较新”。
多值偏好可以并存；新观测不应默认覆盖所有同类旧事实。

### 2.3 生成必须消费记忆内容

通过可训练的门控交叉注意力/残差通路，让记忆内容参与冻结 backbone 的生成计算。
先保留全层读入能力和全秩参数。每层是否共享投影是待对照的设计变量，
不能为了省参数默认强制共享，也不能未经对照就扩大层数或模块数量。

必须保留未被记忆改写的当前对话表示。优先验证“对话上下文正常编码，
在回复位置读入记忆”的方式，并与全位置融合做隔离对照，检查主体是否被污染。
memory reader 能看到当前上下文，不代表可以重写用户问题中的角色和姓名。

精确姓名、数字、日期、标识符可使用受控的 token-level pointer/copy 分支。
它只能复制当前上下文或已被神经激活的事件中经过校验的 payload，
并与词汇生成联合决定逐 token 输出；不能返回整个固定答案模板冒充自然生成。

补充的独立架构对照：经用户确认，DG-003 验证连续输出记忆增量分支，见 `CONTINUOUS_MEMORY.md`。
它保留冻结 C 基础分布，用神经记忆产生连续校正；不是原全层注入已经完成，也不替换现有默认部署。
本对照必须通过数值、真实损失方向、目标排名及后续独立记忆能力验收，不能只看 NLL。

### 2.4 读、写独立，状态有明确生命周期

`WriteDelta` 与 `ReadContext` 是两个独立结果，不使用互斥的 write/read 单分类。
写入决策考虑信息的长期用途、真实性、重复程度、更新意义和保留成本；
新奇程度或语法上的陈述句都不能单独决定是否记忆。

一次普通交流的逻辑过程：

1. 依据应用提供的稳定 `memory_scope` 加载已提交状态；会话 ID 与长期记忆作用域分开。
2. 对当前消息和必要的近期对话重新 prefill，保留说话者和角色信息。
3. 在旧状态的只读快照上激活相关事件，辅助理解指代与更新。
4. 神经 writer 产生候选增量；确定性系统仅校验来源、边界、作用域和操作合法性。
5. 合法增量事务性提交；本轮回复使用一致的只读状态视图和当前消息。
6. decode 期间不修改持久记忆，不自动把助手生成的猜测变成事实。

实现可以拆分预填充次数，但必须证明因果性、视图一致性和数值一致性。
不允许当前查询的参考答案、未来消息或训练标签进入写入/激活的前向输入。
写入失败不能伪报已持久化；普通回复可以继续，失败进入独立诊断与运行指标。

### 2.5 状态、模型与运行策略分离

| 对象 | 内容 | 生命周期 |
| --- | --- | --- |
| `MemoryModel` | writer、地址/关系、reader、融合及复制模块参数和结构 | 离线训练，部署后冻结 |
| `MemoryState` | 各用户实际事件、来源、内容表示、版本边及撤回状态 | 正常交流中按事务更新 |
| `ConversationContext` | 当前窗口、说话者、必要的近期对话 | 暂态，不靠跨请求 KV 维持记忆 |
| `ReadContext` | 神经激活权重、内容向量、有效 payload 地址、可用性信息 | 单次回复内只读 |

最终部署目标是一份自包含的记忆模型权重包，用户记忆数据另存。
二进制格式在结构冻结后再定版，不能复用不兼容的旧格式头或依赖三个不参与计算的兼容模型。
模型和状态需绑定 backbone、tokenizer/输入协议、编码器和格式版本，
只校验 GGUF 哈希不足以证明特征域兼容。

## 3. 模块接口契约

数值实现补充见 `NUMERICAL_CONTRACT.md`：reader 的冻结骨干输入优先验证同一 C 编码器输出的直接复用，
GPU 继续训练记忆模块；此桥接不替代生成融合的可微前向，也不解除 P2B/P2C 的数值门槛。

以下为逻辑接口；字段可细化，但职责不可无记录地合并或改变。

| 模块 | 允许输入 | 输出 | 禁止输入/行为 |
| --- | --- | --- | --- |
| 上下文编码 | 当前/近期自然消息、角色、时间、应用作用域 | 原始上下文表示、神经线索 | 未来消息、参考答案 |
| writer | 上下文表示、必要的已激活记忆、来源位置 | 多个候选单元、操作、置信度、来源绑定 | 用户必须说 remember；把所有输入强制写成 actual |
| compiler/store | 候选增量、当前状态、存储策略 | 校验后的原子提交 | 用关键词/字符串匹配替代语义判断 |
| reader | 神经线索、事件地址/内容/元数据 | 独立事件激活、内容读出、可用性 | gold 主体/关系/目标 ID；原文检索和提示词拼接 |
| generator | 当前上下文、`ReadContext`、当前输出前缀 | 自然回复 token 分布 | 直接把复制值作为整个回复 |
| persistence | 已提交状态、模型身份和作用域 | 自动恢复、快照、迁移拒绝/显式迁移 | 依赖用户手动 export/import 才能日常记忆 |

来源位置和时间等运行元数据可进入接口；训练得到的角色标签与 gold 激活目标不可进入。
原始字节可由明确 payload 指针读取以保证精确复制，但不能按当前问题搜索原文。

## 4. 无记忆与不确定性的契约

必须区分三种情况，避免“没记忆就空回复”与“所有空库行为必须相同”的混淆：

- **记忆功能关闭**：严格保持原 backbone 路径，作为数值回归基线。
- **功能开启、当前不需要记忆**：正常回答，不受无关记忆干扰，不添加记忆操作旁白。
- **回复依赖用户私有信息，但证据缺失/冲突**：自然表达不确定或就内容澄清，不能猜测一个人的事实。

空内容读出应为零注入；是否需要表达不确定由单独的神经可用性/任务判断控制。
此前的 `empty_memory_logits_exact` 只证明组件 bypass 正确，不能替代上述产品验收。
这一语义区分必须先写入测试，不能在看到结果后改口径。

实施核查（DG-004/DG-005）：当前 `GatedMemoryFusion` 只实现内容分支，
空来源返回零增量；冻结 backbone 下该路径的输出不依赖任何可训练参数，
所以不能靠增加空库训练样例让它学会不确定表达。独立神经可用性/任务控制仍是未完成项，
不是用 prompt 规则或固定拒答模板补齐。DG-004 的空库逐位一致仅是现有 bypass 数值对照。
在该控制分支完成并用无目标/普通聊天对照验证前，不能宣称覆盖证据缺失，也不启动要求该能力的训练。

实施进展（DG-006）：已新增独立三状态神经可用性分支，空库生成损失可到达其输出矩阵，
并通过 v2 的本轮数值/后端对照；详见 `AVAILABILITY.md`。这完成了通路原型而非语义能力，
当前随机权重仍会猜错事实。状态标签仅作后置 loss，普通聊天与证据不足的能力需在受控训练后验证。

## 5. 训练设计

训练对象是通用读写规则与生成融合，不是某一套用户事实。
每个训练世界有独立的动态记忆状态；新世界/新用户必须清空该状态。

分阶段训练允许暂时冻结已验证组件做归因实验，但必须明确冻结了什么、为什么。
最终需联合校准 reader、writer 与生成模块，或用有证据的分阶段策略验证组合无退化。
冻结 backbone 参数时仍保留经过它的梯度通路，不能整体 `no_grad()` 截断融合学习。

训练信号包括：

- 是否写入、多个记忆单元的边界、主体/角色与内容的绑定。
- 实际/否定/假设/引用/不确定、时间关系、替代/补充/并存/撤回。
- 事件相关性、无目标拒绝、别名和指代；标签仅作训练监督。
- 自然回复损失、精确 payload 生成、主体保护，以及普通聊天不退化。
- 同问题换记忆值、换主体、删目标、加干扰、调整无关顺序等因果一致性约束。

NLL、字段监督和可用性分类都是辅助证据。推进依据必须包含无参考答案前缀的自由生成。
不能只优化模板中容易预测的词，掩盖第一个回答决策或关键事实 token 的错误。

数据需要逐步覆盖：中英文、第一/第三人称、同名/别名、多主体、多事实、隐式需求、
读写混合、负面/假设陈述、更新和历史、事件顺序、前瞻事项、两跳及集合问题。
先验证小任务，再扩大范围；限定任务成绩不能宣称为这些能力全部完成。

## 6. C 与持久化设计要求

- C 实现以冻结的 Python 模型契约为依据，不能移植过程中补规则以提高分数。
- tokenizer、模板、BOS/EOS、归一化、RoPE、量化、精度及隐藏状态位置都需对齐。
- 同一 GGUF 不代表 Torch 和 C 特征一致；分别核验算子、特征和端到端行为。
- 普通与流式 chat 都支持同一自动记忆语义；诊断字段与自然回复分离。
- 写入成功需自动持久化，重启后自动恢复；export/import 仅作管理和迁移入口。
- 导入损坏、格式不匹配和写入失败不得破坏已有状态。
- 遗忘必须使所有读取路径失效；历史版本、派生表示、复制 payload 和导出都要遵守撤回状态。
- 容量、长输入、并发、会话隔离、模型升级和重复请求必须有明确策略，不能静默丢信息。
- 跨请求与逐步生成都不依赖 backbone KV cache；性能优化需在准确性通过后另做对照。

## 7. 已有实现的地位

`resident-0.5b` 是当前部署对照，不是新方案的成功依据。
`fusion-gate1` 是未通过验收的生成融合实验，其报告保留且不改写为成功。
`episode_memory.py`、`train_episode_memory.py` 是未验证草稿，尚未用于训练；
其中对两个合成关系和单主体的假设不能上升为本设计的通用数据模型。

在 `PLAN.md` 的前置项完成前，不启动这些草稿的训练、不接入生产 C 路径。
本文件中的设计是待验证的工程与研究假设，不保证最终指标或“完美记忆”。
